# Architecture Decision Record

## What It Is

An ADR records one architecturally significant decision and the reasoning around it.

## When To Use It

Use it when future maintainers need more than the resulting code to understand an architectural choice.

## Lifecycle

An ADR moves from proposal through acceptance and may later be superseded without erasing its history.

## Agent Use

Agents can consult accepted ADRs before changing system boundaries and identify superseded records as history.

## Pitfalls

A decision title without context or consequences preserves the outcome while losing the reason.

The ADR community maintains [templates and examples](https://adr.github.io/).
